Recommended implementation order

Recommendation, not implementation authorization. Deliver each as a tested slice.

  1. Daily-use polish and persistence. Save preferred graph, timer/auto-advance choices and plate/bar inventory. Add favorites, last-used hints and accessible ordering controls. Immediate value every workout; no new analytics semantics.
  2. Exercise overview and factual statistics. One hub for existing history/graphs/records. Add workout/set counts, total reps/volume and source-linked bests for selected periods; types and units stay separate. Summaries should remain server-backed.
  3. Exercise goals. Start with actual weight at an exact rep count and max reps. Add estimated goals only with unmistakable labels. Define cutoff, completed-set inclusion, units, achievement evidence and correction behavior before coding.
  4. Selective copying and routine carry-forward. Preview destination and chosen exercises/sets; explicitly choose fixed versus prior values. Preserve completed originals and reset copied performance state. Do not reinterpret existing blank template fields silently.
  5. Cardio analysis and richer calendar filters. Speed/pace and distance/time totals; category markers and filters. Pace improves downward, unlike load. Comparisons must respect units and recorded exercise types.
  6. Sharing/export and gym reliability. Private text sharing and workout CSV, session timing, then offline logging and alert behavior as separate capabilities. Validate real phone/background behavior before promising native-like reliability.

Differences worth keeping

Preserve history

Archive catalog entries. Freeze recorded names/types/units. Do not implement FitNotes-style destructive type changes or relabel old kg quantities as lb.

Reference behavior

Keep records factual

Our exact-rep best is an actually logged set. A higher-rep set can inform a capability estimate, but should not silently become a performed lower-rep record.

Reference precedence rule

One measurement system

Use Metrics for body measurements. A second Body Tracker would duplicate ownership, graphs, exports and goals.

No retroactive basic paywall

Keep the complete basic workout log available to every account. Any advanced Pro decision is separate from FitNotes' Supporter policy.
